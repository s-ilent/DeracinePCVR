### 2.1 Feature negotiation is explicit

The harness queries `VkPhysicalDeviceFeatures2` with the Vulkan 1.1/1.2/1.3 chains, then enables only features the device actually reports. The resulting `DeviceManifest` records what was **enabled**, not what was requested. On the RTX 3090 Ti:

```
timelineSemaphore synchronization2 dynamicRendering multiview
separateDepthStencilLayouts maintenance4 maintenance5 maintenance8
descriptorIndexing bufferDeviceAddress sampleRateShading
geometryShader tessellationShader
maxViewCount: 32   maxColorAttachments: 8   maxFramebuffer: 32768x32768
```

### 2.2 NRI adoption is non-owning

`nriCreateDeviceFromVKDevice` receives the existing `vkInstance`, `vkDevice` and `vkPhysicalDevice`. The test verifies NRI reports the same handles back through `GetDeviceNativeObject`, `GetPhysicalDeviceVK` and `GetInstanceVK`, and that the adopted `VkQueue` matches. Teardown destroys the NRI wrapper first, then the native device.

## 3. Test results with readback evidence

### 3.1 Phase 2 — external image interoperability

| Case | Result |
|---|---|
| Single-layer color, wrap, readback | red as written; NRI handle equals the `VkImage` |
| Wrapper destroyed, image still usable | readback succeeds after `DestroyTexture` |
| Two-layer stereo, per-layer readback | layer 0 green, layer 1 blue |
| Combined depth/stencil, wrap | depth 0.25, stencil 0x5A |
| 4x MSAA image, wrap | wrapped successfully |
| sRGB + linear views over one image | requires `MUTABLE_FORMAT` (see 4.1) |
| 32 wrap/destroy cycles | all succeeded |

**Ownership is verified, not assumed.** After `DestroyWrappedTexture`, the original `VkImage` remains readable. That is the property the OpenXR path depends on.

### 3.2 Phase 3 — depth/stencil aspects

The decisive result:

```
[PASS] depth written to 0.75 by the depth-only pipeline
[PASS] stencil PRESERVED at 0x5A across a depth-only write
```

A pipeline with `stencilTestEnable = VK_FALSE` writing through a **combined** depth+stencil attachment view changed depth and left stencil untouched. This confirms the prior report's caution: **a combined attachment view does not imply writes to both aspects.**

Also verified:
- Depth-only, stencil-only and combined `VkImageView`s all create successfully.
- Independent per-aspect layout transitions execute under `separateDepthStencilLayouts`.
- NRI creates depth-only, stencil-only and combined texture views via `PlaneBits`.

### 3.3 Phase 4 — stereo

| Configuration | Result |
|---|---|
| Sequential, two draws, per-layer views | layer 0 red, layer 1 blue |
| Multiview, `viewMask=0x3`, array view | view 0 red to layer 0, view 1 blue to layer 1 |
| Multiview, `viewMask=0x1` | layer 0 written, **layer 1 untouched** |

The `viewMask=0x1` case is the isolation proof: a nonzero mask does not mean both eyes.

`gl_ViewIndex` works as expected once `GL_EXT_multiview` is declared in the shader.

### 3.4 Phase 5 — submission and lifetime

- Generation-tagged identity: a stale generation does not resolve after retirement.
- Deferred parameter snapshot: immune to later mutation of the source value.
- Timeline semaphore: three submissions, retirement exactly matches the observed completion value.
- Independent completion domains retire separately.
- Oversized dimension detected before narrowing.
- Command buffers freed only after GPU completion.

## 4. Validation-layer findings

The validation layer caught **three real bugs in my own test code**. Each is a finding about the API contract, not just a typo.

### 4.1 sRGB views require MUTABLE_FORMAT

```
VUID-VkImageViewCreateInfo-image-12397: pCreateInfo->format VK_FORMAT_R8G8B8A8_SRGB is
different from VkImage format (VK_FORMAT_R8G8B8A8_UNORM). Formats must be identical
unless VK_IMAGE_CREATE_MUTABLE_FORMAT_BIT was set on image creation.
```

**Implication for the native renderer:** any host that wants sRGB and linear views over one image must create it with `MUTABLE_FORMAT`. The harness now does, and includes a negative test (`case5b`) that proves the constraint is real by deliberately omitting the flag.

### 4.2 Command buffers must outlive their submission

```
VUID-vkFreeCommandBuffers-pCommandBuffers-00047: command buffer is in use.
```

Freeing a command buffer immediately after `vkQueueSubmit` is a lifetime bug. This is exactly the class of error the Phase 5 retention model exists to prevent, and the layer caught it in the test harness itself.

### 4.3 Layout must match the actual previous state

```
VUID-vkCmdBeginRendering-pRenderingInfo-09592: expects COLOR_ATTACHMENT_OPTIMAL,
current layout is UNDEFINED.
```

A freshly created image is in `UNDEFINED`, not in the layout you intend to use. The transition must name `UNDEFINED` as the old layout.

## 5. Prior research hypotheses: confirmed, corrected, rejected

| Hypothesis | Verdict |
|---|---|
| NRI can adopt an existing Vulkan device without owning it | **Confirmed** — handles verified identical, teardown order works |
| NRI can wrap external `VkImage` without destroying it | **Confirmed** — image readable after wrapper destruction |
| NRI rejects `BindMemory` on wrapped objects | **Confirmed by source**; not exercised (no need) |
| Multiview requires matching pipeline and render `viewMask` | **Confirmed** — `0x3`/`0x3` works, `0x1` isolates correctly |
| Two-layer texture support alone is insufficient for multiview | **Confirmed** — `maxViewCount` and the feature bit both matter |
| A combined depth/stencil attachment view implies both aspects are written | **Rejected** — stencil preserved across a depth-only write |
| Depth and stencil can be transitioned independently | **Confirmed** under `separateDepthStencilLayouts` |
| `program_data+0x06` could serve as a shader hash | **Not tested here**; still unsupported by evidence |
| Sequential stereo is an acceptable correctness baseline | **Confirmed** — it works and is simpler than multiview |

### 5.1 One correction to the prior plan

The FOUNDATION report proposed a "backend-neutral operation tape" and a cross-library benchmark as the first experiment. That was premature. The actual first blocker was simpler: **nothing had ever executed on a GPU.** Establishing a working device, verified image interoperability and verified aspect behaviour had to come first, and did.

## 8. Semantic RHI boundary (Phase 7)

`src/common/semantic_rhi.h` defines a backend-independent interface covering exactly the operations the harness exercises: texture and buffer creation, views, shaders, pipelines, shader parameters, binding, render-target selection, viewport and scissor, transitions, clears, copies, resolves, draw, dispatch, submission and completion.

Design constraints honoured:

- **No Vulkan or NRI types appear in the header.** A different backend can implement it.
- **Original resource identity is separate from host identity.** `ResourceId` is `{index, generation}`, not a pointer.
- **No Déraciné-specific addresses, structures or ABI mappings are invented.** The interface describes operations, not recovered game internals.

### 8.1 How recovered UE4 operations would populate it

| Recovered UE4 operation | Semantic RHI call |
|---|---|
| Shader resource creation (`0x135B9B0` family) | `CreateShader` |
| Shader-state binding (`0x0CBE210`) | `BindPipeline` + `SetShaderParameters` |
| Slot selection (`0x0CCC2F0`) | `BindPipeline` |
| Render-target binding | `BeginRenderPass` |
| Viewport command | `SetViewport` |
| Indexed draw (`0x0CBB9C0`) | `DrawIndexed` |

This is a **mapping of operations**, not a claim that the recovered addresses are correct for any specific build. The addresses come from the separate binary-reconstruction track.

## 12. Summary

**Working:** a standalone Vulkan/NRI harness that creates a device, adopts it into NRI, imports external images without ownership transfer, validates depth/stencil aspect independence, renders stereo both sequentially and with multiview, and retires resources on real GPU completion. 68 assertions, zero validation errors, on an RTX 3090 Ti.

**Corrected:** the prior plan's first experiment was premature. Execution had to come first.

**Rejected:** the assumption that a combined depth/stencil attachment view implies writes to both aspects. It does not, and the harness proves it.

**Blocked:** OpenXR, on missing SDK headers. The runtime and loader are present.

**Unchanged:** the native shader execution blocker. Nothing here produces PC-executable shaders from PS4 shader binaries.
