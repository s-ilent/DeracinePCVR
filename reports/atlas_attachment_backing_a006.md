# A-006 — Attachment resource backing-object and graphics-state emission (original SELF)

**Status:** original-SELF byte-verified static finding, no runtime reachability. Target SHA-256 `8caee78e40693b2e57c68ce87ce9507d907b824b6f6a4c481f414ac0627011a0`, size 81,506,767. Independently rehashed before decoding. Base: atlas A-005 at `a675d3dd3d0991a280e97cce871c65b175d63a2e`. A-005 already established the call `0x0CC251E → 0x0CC7E00`; that edge alone is not new.

## New independently decoded original-byte evidence

1. **Resource → backing object → state encoding.** At ELF VA `0x0CC7E33`, helper tests its incoming resource pointer (`RDX` saved as `R13`). On the non-null branch, `0x0CC7E43` loads the resource's vptr, `0x0CC7E4A` calls virtual slot **+0x38** with `RDI=resource`, and `0x0CC7E4D` retains the returned pointer as `R14`. `0x0CC7E53` reads DWORD **[backing+0x3C]** and `0x0CC7E57` calls direct callee `0x0CC9240` with `RDI=context`, `ESI=[backing+0x3C]`. Thus the +0x38 method supplies a backing/state object; its exact C++ type is unknown. The helper also reads/writes backing fields `+0x08,+0x0C,+0x10` under a global conditional at `0x0CC7E69–0x0CC7E93`. The null-resource branch at `0x0CC7E97` clears the backing pointer.
2. **New state-emission callee.** `0x0CC9240` computes a packed field from the backing DWORD: `value & 7`, replicated into bit positions 0, 8, 12, and, for positive values, sets bit 20. It checks context state `+0x480,+0x484` and writes a 12-byte command into the context's writer at **[context+0x460]** when state differs. The writer's begin/end pointers are at **+0x10/+0x08**, and the growth callback is **+0x18** (capacity check and conditional call at `0x0CC9293–0x0CC92B8`).
3. **Two distinct state transitions.** Positive and non-positive branches at `0x0CC926B` emit different 12-byte words with the same leading 64-bit constant `0x292C0016900` but trailing DWORD **3** or **2** respectively, then update the pair at `[context+0x480]`. Both converge at `0x0CC9359`, where another 12-byte command is emitted: QWORD **`0x201C0016900`**, followed by the packed field masked with **`0x0F3F7777`**. At `0x0CC93AB`, the writer is passed to `0x2F5D0F0` with the original value. These are exact encoded DWORD-stream observations, **not** a claimed GPU packet semantic decoding.
4. **Conditional fast path in attachment helper.** At `0x0CC7F5F`, `[context+0x460]` is again read; its writer capacity is checked before an 0x11-DWORD reservation. This independently corroborates that `0x0CC7E00` operates on a graphics command writer as well as resolving the resource backing object.

## Address provenance / limits

All addresses above are **inner ELF virtual addresses**. Checked executable mapping: original SELF offset = ELF VA + **0x1FD30**; hence `0x0CC7E00 → 0x0CE7B30`, `0x0CC9240 → 0x0CE8F70`, `0x0CC7E4A → 0x0CE7B7A`, `0x0CC9359 → 0x0CE9089`. These are not loaded guest pointers, GPU virtual addresses or shader hashes. Decode using `objdump -D -b binary -m i386:x86-64 -M intel --adjust-vma=<ELF VA>` on the private original SELF's bounded windows. See `tools/atlas/verify_attachment_backing_a006.py` for byte/edge assertions.

**Confidence:** high for resource virtual +0x38 → backing object +0x3C → state-emitter and command-writer path; moderate for graphics-state classification; **unknown** for backing ownership, retain/release semantics, depth-vs-colour meaning and precise packet interpretation. A virtual +0x38 return is not evidence of allocation or lifetime transfer. No FDE or RTTI identification is asserted; function boundaries were checked at prologue and instruction-contiguous windows, not proven as full unwind ranges. Further work: recover the resource's vtable producer and +0x38 target(s), then decode the full writer path and cross-check state packet meanings.
